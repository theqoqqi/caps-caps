# Дорожная карта разработки CapsCaps (Roadmap)

Пошаговый план реализации с изолированными вертикальными срезами. Каждый шаг компилируется, проверяется и даёт работающий инкремент функциональности.

---

## Регламент автономной работы и коммитов

- **Разрешение на коммиты:** пользователь дал явное разрешение на автономное выполнение задач из этого роадмапа и создание git-коммитов после каждого шага.
- **Строгий порядок действий на каждом шаге:**
  1. Выполнить изменения текущего незавершенного шага, соблюдая стиль кода из [`AGENTS.md`](../AGENTS.md).
  2. Проверить сборку через `dotnet build` и запуск тестов через `dotnet test`. Убедиться в отсутствии ошибок.
  3. Отметить `[x]` в чекбоксе текущего шага в этом файле.
  4. Выполнить `git add` всех затронутых файлов.
  5. Сделать git-коммит с сообщением, точно указанным в пункте «Коммит» каждого шага.
  6. Переходить к следующему шагу строго после успешного коммита.

## Фаза 1. Каркас и базовое окружение

- [ ] **1. Зависимости проекта**
  - Подключить пакеты `ModernWpfUI` (0.9.6) и `H.NotifyIcon.Wpf` (2.4.1) в `CapsCaps.csproj`.
  - Проверить сборку: `dotnet build`.
  - Коммит: `build: Подключить зависимости ModernWpfUI и H.NotifyIcon.Wpf`
- [ ] **2. Тестовый проект**

  - Проверить тесты: `dotnet test`.
  - Коммит: `test: Создать проект CapsCaps.Tests на xUnit`
- [ ] **3. Утилитный проект**
  - Создать проект библиотеки классов `CapsCaps.Shared` (.NET 8) в решении.
  - Проверить сборку: `dotnet build`.
  - Коммит: `feat: Создать проект библиотеки утилит CapsCaps.Shared`
- [ ] **4. Перенос утилит из QuietShell**
  - Скопировать `JsonFileStorage.cs` и подсистему `DataProtection` из `QuietShell.Shared` в `CapsCaps.Shared` без изменения контрактов.
